The clock (PJCC_TIME) is INLINED rather than loaded from /assets/js/pjcc-time.js. It's ~2.5 KB and it has to run BEFORE first paint (the weather class must be on or you get a flash of clear sky), so as an external file it was a render-blocking round-trip on every single page. Inlined, it costs zero requests. The source of truth is _includes/pjcc-time.js — edit it there. Then pjcc-weather-canvas.js (the particle engine) and pjcc-weather.js (the driver that reads the forecast and starts it) build the falling weather. ⚠ ORDER MATTERS and `defer` is what makes it safe: deferred scripts run in DOCUMENT ORDER, so the engine has defined window.PJCCWeather by the time the driver calls PJCCWeather.start(). Swap these two lines and the driver finds nothing, silently falls back to "no falling weather", and you get a clear sky on a rainy day with no error in the console — the exact shape of bug that cost us a week once before (a feature shipped but never loaded). {%- endcomment -%} {%- comment -%} Both classes go on BEFORE first paint, so there's no flash of the wrong sky/weather. `sky-` used to be set on by the home page only — which meant the whole day/night clock existed on ONE page while the weather fell on every page.
